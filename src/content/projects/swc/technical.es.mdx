## Arquitectura

Es una aplicación Next.js 16 (App Router) sin base de datos: el estado de cada empresa vive en el navegador con Zustand. El código sigue una arquitectura hexagonal. `src/core` es TypeScript puro (reglas, PESTEL, briefing, onboarding) y define puertos como `source-adapter`, `signal-analyzer`, `clock` y `logger`. `src/infrastructure` implementa esos puertos con las fuentes de datos y la IA. `src/features/*` agrupa la interfaz por dominio.

## Decisiones clave

- **Núcleo hexagonal verificado por una prueba.** Una prueba de arquitectura falla si `src/core` importa infraestructura. Las reglas se pueden probar sin red y cambiar de fuente sin tocarlas.
- **Reglas legibles como funciones puras.** Cada regla (movimiento diario de la TRM, contrato por vencer, contrato nuevo de un competidor, variación semanal de la energía, palabra clave en noticias o regulación) es una función pequeña, con un umbral ajustable. Un aviso siempre muestra qué regla lo generó.
- **Sin base de datos.** El perfil de cada empresa se guarda en el navegador. Reduce la superficie de datos y el costo de operar, a cambio de que el estado no se comparta entre dispositivos.
- **Asistente de solo lectura, no RAG.** Ocho herramientas (`get_trm`, `get_secop_contracts`, `get_competitor_financials`, `get_macro_series`, `get_news`, `get_regulation`, `get_energy_price`, `detect_signals`) consultan los datos vivos. No hay embeddings ni almacén vectorial. El prompt de sistema trata el contenido externo como no confiable para resistir inyección de instrucciones.
- **Modelo con respaldo.** OpenAI `gpt-4.1-mini` por defecto y OpenRouter como alternativa. Sin clave, la aplicación sigue funcionando y el asistente avisa que no está configurado.
- **Seguridad en el borde y en la app.** Cloudflare Access con inicio de sesión de Google protege todo salvo la landing. La aplicación valida además el JWT (RS256, `jose`) y responde 503 si falta la configuración. Los encabezados incluyen CSP en modo reporte y HSTS.

## Pruebas, CI y despliegue

- Vitest con 181 archivos de prueba y Testing Library; Playwright cubre el asistente, la configuración, la landing y un recorrido de humo.
- GitHub Actions ejecuta la integración continua. Linting con oxlint.
- Despliegue en Vercel con cada push a `main` y un Dockerfile multi-etapa (salida standalone, usuario sin privilegios) para el entorno productivo del cliente.
- El repositorio no se enlaza aquí porque identifica al cliente.
