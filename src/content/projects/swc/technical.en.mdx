## Architecture

A Next.js 16 (App Router) application with no database: each company's state lives in the browser with Zustand. The code follows a hexagonal architecture. `src/core` is pure TypeScript (rules, PESTEL, briefing, onboarding) and defines ports such as `source-adapter`, `signal-analyzer`, `clock` and `logger`. `src/infrastructure` implements those ports with the data sources and the AI. `src/features/*` groups the interface by domain.

## Key decisions

- **A hexagonal core enforced by a test.** An architecture test fails if `src/core` imports infrastructure. Rules can be tested without a network, and a source can change without touching them.
- **Readable rules as pure functions.** Each rule (daily TRM move, expiring contract, new competitor contract, weekly energy change, keyword in news or regulation) is a small function with an adjustable threshold. An alert always shows which rule produced it.
- **No database.** Each company's profile is stored in the browser. This reduces the data surface and the operating cost, at the price of state not being shared across devices.
- **A read-only assistant, not RAG.** Eight tools (`get_trm`, `get_secop_contracts`, `get_competitor_financials`, `get_macro_series`, `get_news`, `get_regulation`, `get_energy_price`, `detect_signals`) query live data. There are no embeddings and no vector store. The system prompt treats external content as untrusted to resist instruction injection.
- **A model with a fallback.** OpenAI `gpt-4.1-mini` by default and OpenRouter as the alternative. Without a key the app keeps working and the assistant says it is not configured.
- **Security at the edge and in the app.** Cloudflare Access with Google sign-in protects everything except the landing page. The app also validates the JWT (RS256, `jose`) and answers 503 if the configuration is missing. Headers include CSP in report-only mode and HSTS.

## Testing, CI and deployment

- Vitest with 181 test files and Testing Library. Playwright covers the assistant, settings, the landing page and a smoke path.
- GitHub Actions runs continuous integration. Linting with oxlint.
- Deployment on Vercel on every push to `main`, and a multi-stage Dockerfile (standalone output, non-root user) for the client's production environment.
- The repository is not linked here because it identifies the client.
