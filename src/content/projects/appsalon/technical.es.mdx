## Arquitectura

Monolito Laravel 13 (PHP 8.4) con Inertia 3: los controladores devuelven páginas React en lugar de JSON, así que no hay una API separada. MySQL 8 corre en Docker. Los reportes PDF salen por una cola de base de datos.

## Decisiones clave

1. **Inertia en vez de una API y un SPA aparte.** Laravel mantiene el enrutamiento, la autorización y la validación, y React solo renderiza. Es un solo despliegue y un solo contrato.
2. **Roles con middleware.** `cliente`, `funcionario` y `admin` se guardan en `usuarios.rol`. Los grupos de rutas `funcionario` y `admin` aplican `FuncionarioMiddleware` y `AdminMiddleware`.
3. **Reserva sin cuenta con token.** `ReservaPublicaController` comprueba los horarios ocupados y emite un `token_seguimiento` que alimenta la página pública de estado.
4. **Reportes PDF asíncronos.** Un job con reintentos y tiempo límite evita bloquear la petición. Una capa de Actions y DTOs en `app/Reportes` aísla la lógica, y un comando programado limpia los reportes vencidos cada día.
5. **Importación con vista previa.** El flujo de Excel valida las filas, las muestra, las revalida y solo entonces las inserta.
6. **Búsqueda con FULLTEXT de MySQL.** El catálogo de servicios usa un índice `MATCH ... AGAINST` sobre nombre y descripción, sin servicio de búsqueda aparte.

## Pruebas, CI y despliegue

Pest 4 cubre 12 archivos de pruebas de feature: autenticación (6), panel, reportes PDF y ajustes de perfil y seguridad, incluido el desafío de dos factores. GitHub Actions ejecuta las pruebas (PHP 8.4, Node 22) y un flujo de lint. El estilo se controla con Laravel Pint, ESLint y Prettier. Sin instancia desplegada: el desarrollo local usa Docker Compose para MySQL.
