## Architecture

A Laravel 13 monolith (PHP 8.4) with Inertia 3: controllers return React pages instead of JSON, so there is no separate API. MySQL 8 runs in Docker. PDF reports go through a database queue.

## Key decisions

1. **Inertia instead of a separate API and SPA.** Laravel keeps routing, authorization and validation, and React only renders. One deployment, one contract.
2. **Roles through middleware.** `cliente`, `funcionario` and `admin` are stored in `usuarios.rol`. The `funcionario` and `admin` route groups apply `FuncionarioMiddleware` and `AdminMiddleware`.
3. **Guest booking with a token.** `ReservaPublicaController` checks occupied slots and issues a `token_seguimiento` that feeds the public status page.
4. **Asynchronous PDF reports.** A job with retries and a timeout keeps the request from blocking. A layer of Actions and DTOs in `app/Reportes` isolates the logic, and a scheduled command cleans expired reports daily.
5. **Import with preview.** The Excel flow validates rows, shows them, revalidates them and only then inserts.
6. **MySQL FULLTEXT search.** The service catalog uses a `MATCH ... AGAINST` index over name and description, with no separate search service.

## Testing, CI and deployment

Pest 4 covers 12 feature test files: authentication (6), dashboard, PDF reports and profile and security settings, including the two-factor challenge. GitHub Actions runs the tests (PHP 8.4, Node 22) and a lint workflow. Style is enforced with Laravel Pint, ESLint and Prettier. There is no deployed instance: local development uses Docker Compose for MySQL.
