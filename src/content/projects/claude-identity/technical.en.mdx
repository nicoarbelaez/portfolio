## Architecture

`cid` is a single Go binary (`cmd/cid`) with its logic in `internal/`. The Claude Code plugin is Markdown and JSON: a hook calls `cid hook` and skills invoke the CLI. Each account's credentials are stored in the OS keyring.

## Key decisions

1. **OS keyring as the store.** `cid` does not implement its own OAuth: login runs `claude auth login` in an isolated temp directory and the credentials end up in Windows Credential Manager, macOS Keychain or Linux Secret Service, through `go-keyring`.
2. **A swap that can be undone.** It waits for Claude Code's lock files, verifies the login after writing and restores the previous one if anything fails. Before building it I ran an experiment (`docs/spikes/r2-hot-swap.md`) showing the hot swap was viable.
3. **A hook with no model and no shell.** `/account` resolves through a `UserPromptExpansion` hook that runs `cid hook`, so it answers instantly and uses no turn.
4. **Auto-switch with anti-flap rules.** A principal account and reserves, with a 5-point headroom and 5 minutes between switches, so it does not bounce back and forth near the limit.
5. **Failure-resistant files.** Atomic writes, `flock` locking and recovery of corrupt files from a `.bak` copy. JSON schemas validate the configuration.
6. **Stable contract.** `--json` output and exit codes 0/1/2, so scripts can depend on the CLI.

## Testing, CI and deployment

41 test files. GitHub Actions runs `gofmt`, `go vet` and `go test -race ./...` on Ubuntu, macOS and Windows, plus a lint job, CodeQL and Dependabot. Actions are pinned by commit SHA. release-please picks versions from conventional commits and GoReleaser publishes binaries for Windows, macOS and Linux on amd64 and arm64. The installers (`install.ps1`, `install.sh`) verify SHA-256 and use `gh attestation verify` when `gh` is present. Current version: v0.9.0.
