## Arquitectura

`cid` es un binario único en Go (`cmd/cid`) con la lógica en `internal/`. El plugin de Claude Code es Markdown y JSON: un hook llama a `cid hook` y las skills invocan al CLI. Las credenciales de cada cuenta se guardan en el llavero del sistema.

## Decisiones clave

1. **Llavero del sistema como almacén.** `cid` no implementa un OAuth propio: el login lo hace `claude auth login` en un directorio temporal aislado y las credenciales quedan en Windows Credential Manager, macOS Keychain o Linux Secret Service, vía `go-keyring`.
2. **Un swap que puede deshacerse.** Espera los lock files de Claude Code, verifica el login tras escribir y restaura el anterior si algo falla. Antes de implementarlo hice un experimento (`docs/spikes/r2-hot-swap.md`) que demostró que el cambio en caliente es viable.
3. **Hook sin modelo ni shell.** `/account` se resuelve con un hook `UserPromptExpansion` que ejecuta `cid hook`, así que responde al instante y no consume un turno.
4. **Auto-switch con reglas anti-oscilación.** Una cuenta principal y otras de reserva, con un margen de 5 puntos y 5 minutos de separación entre cambios, para que no alterne sin parar cerca del límite.
5. **Archivos a prueba de fallos.** Escritura atómica, bloqueo con `flock` y recuperación de archivos corruptos con copia `.bak`. Los esquemas JSON validan la configuración.
6. **Contrato estable.** Salida `--json` y códigos de salida 0/1/2, para que otros scripts dependan del CLI.

## Pruebas, CI y despliegue

41 archivos de prueba. GitHub Actions corre `gofmt`, `go vet` y `go test -race ./...` en Ubuntu, macOS y Windows, más un job de lint, CodeQL y Dependabot. Las acciones están fijadas por SHA de commit. release-please decide las versiones a partir de commits convencionales y GoReleaser publica binarios para Windows, macOS y Linux en amd64 y arm64. Los instaladores (`install.ps1`, `install.sh`) verifican SHA-256 y usan `gh attestation verify` cuando `gh` está presente. Versión actual: v0.9.0.
