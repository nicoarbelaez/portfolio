## Arquitectura

El repositorio tiene tres piezas independientes. `defi` es un script de Google Apps Script ligado a la hoja del cliente. `defi-db` es otro script que funciona como base de datos interna y publica JSON mediante una web app (`doGet`). `api` es un servicio Express desplegado en Vercel que dibuja el mapa muscular. La app AppSheet de intercambios de alimentos no está en el repositorio.

## Decisiones clave

- **TypeScript y clasp sobre Apps Script.** El editor web de Apps Script no ofrece tipos ni control de versiones. Con clasp el código vive en Git, se compila y se sube con `pnpm push`.
- **Una base de datos que es una web app.** La hoja del cliente y la fuente de datos están separadas: `defi-db` guarda el catálogo en sus propias hojas y lo sirve como JSON. Cambiar un ejercicio no obliga a tocar la hoja de cada cliente.
- **Debounce y caché.** Cada edición en `#Ejercicios` o `Enlaces` espera 3500 ms antes de regenerar el JSON y lo guarda en PropertiesService, para no recalcular con cada tecla ni en cada lectura.
- **Modelo entidad-relación en hojas.** `defi-db` normaliza el catálogo en las hojas `codigo_ejercicios` y `ejercicios`, de modo que las listas dependientes salen de relaciones y no de rangos copiados.
- **La imagen se genera fuera de Apps Script.** Convertir SVG a PNG o JPG requiere `sharp`, una librería nativa que Apps Script no ejecuta. Por eso es un servicio Express aparte en Vercel; cheerio colorea los músculos sobre la plantilla SVG.
- **Endpoint con límites.** La ruta de músculos tiene límite de peticiones (`express-rate-limit`), registro con morgan y manejo de errores centralizado.

## Pruebas, CI y despliegue

- Los scripts se publican con `clasp` (`pnpm push` y `pnpm pull`) y la API se despliega en Vercel.
- El repositorio no incluye pruebas automatizadas ni CI.
