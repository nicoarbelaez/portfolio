## Architecture

The repository has three independent pieces. `defi` is a Google Apps Script bound to the client's sheet. `defi-db` is another script that acts as an internal database and publishes JSON through a web app (`doGet`). `api` is an Express service deployed on Vercel that draws the muscle map. The AppSheet food-exchange app is not in the repository.

## Key decisions

- **TypeScript and clasp on top of Apps Script.** The Apps Script web editor has no types and no version control. With clasp the code lives in Git, compiles, and ships with `pnpm push`.
- **A database that is a web app.** The client sheet and the data source are separate: `defi-db` keeps the catalog in its own sheets and serves it as JSON. Changing an exercise does not mean touching every client's sheet.
- **Debounce and cache.** Each edit in `#Ejercicios` or `Enlaces` waits 3500 ms before regenerating the JSON and stores it in PropertiesService, so it is not recalculated on every keystroke or every read.
- **Entity-relationship model in sheets.** `defi-db` normalizes the catalog into the `codigo_ejercicios` and `ejercicios` sheets, so dependent lists come from relations and not from copied ranges.
- **The image is generated outside Apps Script.** Converting SVG to PNG or JPG needs `sharp`, a native library that Apps Script cannot run. That is why it is a separate Express service on Vercel, with cheerio coloring the muscles on the SVG template.
- **A rate-limited endpoint.** The muscles route has a request limit (`express-rate-limit`), morgan logging and centralized error handling.

## Testing, CI and deployment

- Scripts are published with `clasp` (`pnpm push` and `pnpm pull`) and the API is deployed on Vercel.
- The repository includes no automated tests and no CI.
