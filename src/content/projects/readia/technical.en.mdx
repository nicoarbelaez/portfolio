## Architecture

The Next.js 15 front end (App Router) handles the session and the UI. AI orchestration lives in three Supabase Edge Functions written in Deno. They authenticate with the user's JWT and write to PostgreSQL under RLS.

## Key decisions

1. **AI in Edge Functions, not in the Next.js server.** Generation logic sits next to the database and reuses the user's JWT, with no extra backend to run.
2. **Provider fallback chain.** `_shared/ai.ts` tries Gemini 2.5 Flash Lite twice, then OpenRouter twice, and logs the attempts. A provider outage does not block the diagnostic.
3. **Structured output with Zod.** The diagnostic (score, pillars, recommendations, distributions, conclusions) is validated against a schema before it is saved. A malformed response fails early.
4. **RLS as the security boundary.** Tables in the `public_web` schema have Row Level Security. The roadmap function also checks that the business belongs to the user.
5. **Roadmap as a graph in the database.** Phases and tasks are stored as `roadmap_nodes` and `roadmap_edges`. React Flow draws them and dagre computes the layout, so a node's status updates without regenerating anything.
6. **PDF on the client.** `@react-pdf/renderer` builds the report from data already loaded, with no separate rendering service.

## Testing, CI and deployment

The repository has no automated tests and no CI. Quality relies on TypeScript, ESLint and Prettier. Database types are generated with the Supabase CLI (`pnpm gen:types`). The front end is live at [readia.arbelaeznicolas.dev](https://readia.arbelaeznicolas.dev).
